# Deck — Marp

The slides are plain Markdown in [`slides.md`](slides.md). The look lives in
[`theme/straightpath.css`](theme/straightpath.css). Nothing else is generated by hand.

## One-time setup

```powershell
npm install
```

Requires Node (installed via `winget install OpenJS.NodeJS.LTS`). Node is needed to
*author and build* the deck — not to present it. The built HTML and PDF need nothing.

## Authoring

```powershell
npm run dev      # live preview, rebuilds as you type
npm run serve    # serves the whole folder at localhost:8080
```

Better option: install the **Marp for VS Code** extension
(`marp-team.marp-vscode`) and open `slides.md`. You get a live preview pane
beside the editor, which is the fastest way to work.

For the preview to pick up the custom theme, add this to VS Code settings:

```json
"markdown.marp.themes": ["./theme/straightpath.css"]
```

## Building

```powershell
npm run build    # html + pdf + notes pdf + pptx
npm run html     # deck.html      — present from this
npm run pdf      # dist/deck.pdf  — backup / handout
npm run notes    # dist/deck-with-notes.pdf — notes as PDF comment annotations
npm run pptx     # dist/deck.pptx — see caveat below
npm run png      # dist/slide.NNN.png — one image per slide
```

`npm run notes` attaches each slide's speaker note as a PDF **comment annotation**
(one sticky note per page, same 17 pages) — not as printed text under the slide. Open
the comments pane in Acrobat or Edge to read them. For notes while presenting, use
presenter view in `deck.html` instead.

**Present from `deck.html`.** Double-click it — no server, no Node, no network.
Arrow keys advance. Press <kbd>F</kbd> for fullscreen, <kbd>P</kbd> for presenter
view (notes + timer + next slide, on the second monitor).

Keep `dist/deck.pdf` on the same USB stick. If you end up on the organiser's laptop,
that is what you open.

### Caveat: the PPTX export is images, not slides

`npm run pptx` produces one PNG per slide with **zero editable text**. It opens in
PowerPoint and projects fine, but nobody can edit it and screen readers get nothing.
It is a delivery format, not a way back to PowerPoint. If an organiser wants the
slides, send the PDF in the session folder. The last editable PowerPoint version of
this talk (a different, older agenda) is in `../../1 - History/2025-05-20 - TFAB/`.

### The PDF beside the Scripts folder

`Intro to PowerShell Automation for the SQL Server DBA - SQLSATBOS.pdf`, one level
up, is `dist/deck.pdf` copied out so it is committed — `dist/` is gitignored, and
attendees browsing GitHub need the slides. Rebuild and re-copy it if `slides.md`
changes.

## Layout

| Path | What |
|---|---|
| `slides.md` | all slide content, front-matter at the top |
| `theme/straightpath.css` | the theme — Straight Path palette from the 2025 brand template |
| `assets/qr-code.png` | deck-local copy of the session QR |
| `.marprc.yml` | points Marp at `theme/`, enables local file access |
| `deck.html` | built output — **must stay next to `assets/`** |
| `dist/` | pdf, pptx, pngs (these embed images, so location does not matter) |

`deck.html` and `dist/` are gitignored; `slides.md`, the theme and `assets/` are the
source of truth.

### Why `assets/qr-code.png` is a copy

It duplicates `../../graphics/QR Code.png`. Marp writes image paths into the HTML
relative to the *output* file, so a path that resolves from `slides.md` breaks from
`deck.html`. Keeping the image beside the built HTML is the simplest thing that works
in every export. If you regenerate the session QR, copy it here too.

## Writing slides

- `---` on its own line starts a new slide.
- `###### Text` is the red uppercase eyebrow above the title — the deck's one motif.
- `<!-- comment -->` after a slide's content is a **speaker note**. It shows in
  presenter view and in the notes PDF, never on the slide.
- `<!-- _class: lead -->` makes a dark title/closing slide.
- `<!-- _class: two-col -->` flows that slide's bullets into two columns.
- Code fences get real syntax highlighting — use ```` ```powershell ````.
- `> quoted text` renders as a grey pull-callout.

## Where the QR code goes

`assets/qr-code.png` encodes `https://bit.ly/4m05kBy?r=qr`, which redirects to the
session's `ResourceList.md` on GitHub — the same link printed on the closing slide.
ResourceList links to this event's folder, so the QR never needs repointing; update
ResourceList for each new event instead. (Checked 2 October 2026.)
